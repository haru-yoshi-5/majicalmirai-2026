# ことばの湖、ひびく未来
## Magical Mirai 2026 Programming Contest Project Spec

## 1. 作品概要

本作品は、マジカルミライ2026 プログラミングコンテスト向けのWebリリックアプリである。

マジカルミライ2026のテーマ「湖のソナーレ」から着想を得て、歌詞を“湖に落ちる言葉”として表現する。

ユーザーが心に残った歌詞を選ぶと、その言葉が湖に落ち、波紋・反射・光の線となって水面に残っていく。
曲が進むにつれて、静かな湖面に選ばれた言葉の痕跡が重なり、最後にはユーザーだけの“湖面アート”が完成する。

これは単なる歌詞表示アプリではなく、歌詞に触れ、湖に響かせ、自分だけの作品として残すリリック体験である。

## 2. 仮タイトル

主タイトル：
ことばの湖、ひびく未来

英語表記候補：
- Lyric Lake Atelier
- Echoes on the Lyric Lake
- Words Resonating on the Lake

現時点では日本語タイトル「ことばの湖、ひびく未来」を主タイトルとする。

## 3. コンセプト

一文コンセプト：

心に残った歌詞を湖に落とすと、波紋と光が広がり、1曲の終わりに自分だけの湖面アートが完成するリリックアプリ。

体験の核：

- 歌詞を読む
- 歌詞に触れる
- 歌詞を湖に落とす
- 言葉が波紋となって響く
- 選んだ言葉が水面に反射して残る
- 曲の最後に、自分だけの湖面アートが完成する

## 4. 目指す方向性

本作品は、ゲーム寄りではなくアート寄りの作品として制作する。

スコア、コンボ、勝敗、ミス判定は不要。
ユーザーがどの言葉を選んでも正解であり、その選択によって湖の表情が変化する。

重視する雰囲気：

- 詩的
- 幻想的
- 静謐
- 透明感
- 創作的
- 余韻がある
- 音楽が水面に響いていく感覚

避けたい方向性：

- 音ゲー風になりすぎる
- UIがゲームっぽくなりすぎる
- スコアや評価でユーザーをジャッジする
- 派手なだけで歌詞が読みにくい
- 湖テーマが薄れる
- ただの綺麗な歌詞表示で終わる

モチーフ：

## 6. 画面構成

基本画面は以下の構成にする。

1. 背景全体に湖面Canvas
2. 中央〜やや上に現在の歌詞
3. 湖面上にクリック可能な歌詞または言葉
4. 選ばれた言葉は湖面上に残る
5. 選ばれた言葉同士が光の線でつながる
6. 下部に小さな再生UI
7. 曲終了時にエンディングオーバーレイを表示

## 7. ユーザー体験

初期状態：

画面には静かな湖が表示される。
水面には小さな光の粒が漂っている。
UIは控えめで、まず鑑賞アプリとして美しく見えることを重視する。

再生開始：

曲の進行に合わせて歌詞が表示される。
歌詞は単に表示されるのではなく、水面の上に浮かぶように現れる。

歌詞選択：

ユーザーが歌詞をクリックすると、以下が発生する。

1. クリック位置から波紋が広がる
2. 選ばれた言葉が selectedWords に保存される
3. 選ばれた言葉が湖面に半透明で残る
4. 文字がゆっくり揺れる
5. 光の粒が少し増える
6. 言葉の種類に応じて色や波紋の性質が少し変化する

曲の進行：

時間帯によって演出を変える。

- intro：静かな湖。小さな光だけが漂う
- verse：小さな波紋と言葉の反射
- preChorus：光の粒と反射文字が少し増える
- chorus：湖面が明るくなり、光の線が強まる
- bridge：一度静かになり、過去に選んだ言葉が浮かぶ
- finalChorus：選んだ言葉が一斉に光り、湖面アートが完成に近づく
- outro：完成した湖面アートをゆっくり見せる

終了時：

曲が終わると、完成した湖面アートの上にエンディング表示を出す。

表示例：

あなたが描いた湖

ひかりのソナーレ

選ばれた言葉：
未来、声、光、響く

## 8. 機能要件

### 8.1 湖面Canvas

Canvasで湖面背景を描画する。

必須要素：

- 暗めのグラデーション背景
- 水面らしいゆるやかな揺らぎ
- 横方向の反射光
- 小さな光の粒子
- requestAnimationFrameによるアニメーション
- 画面リサイズ対応

### 8.2 モックプレイヤー

TextAlive連携前でも動作確認できるように、モックプレイヤーを実装する。

必要な機能：

- 再生
- 一時停止
- リセット
- 現在時刻
- 進行バー
- 曲終了判定

### 8.3 モック歌詞

まずは仮歌詞データを用意する。

mockLyricsの例：

```ts
export const mockLyrics = [
  { time: 0, text: "静かな湖に" },
  { time: 4, text: "ひとつの声が落ちる" },
  { time: 8, text: "波紋は未来へ広がって" },
  { time: 12, text: "きみの言葉を光に変える" },
  { time: 16, text: "夜空を映した水面に" },
  { time: 20, text: "まだ知らない歌が揺れる" },
  { time: 24, text: "響け ひかりのソナーレ" },
  { time: 28, text: "この湖から未来へ" },
  { time: 32, text: "選んだ言葉が星になる" },
  { time: 36, text: "重なる波が道を描く" },
  { time: 40, text: "もう一度 声を届けて" },
  { time: 44, text: "きみだけの湖が光る" },
  { time: 48, text: "響け ひかりのソナーレ" },
  { time: 52, text: "未来の空へ広がって" },
  { time: 56, text: "この歌が水面に残る" },
  { time: 60, text: "ことばの湖、ひびく未来" }
];
```

### 8.4 歌詞表示

現在時刻に応じて歌詞を表示する。

要件：

- 現在の歌詞を中央付近に表示
- 歌詞は少し浮遊感を持たせる
- クリック可能にする
- 選択済みでも再クリックできてよい
- 表示切り替えは急すぎず、フェードを入れる

### 8.5 波紋

クリック位置から波紋を生成する。

波紋の仕様：

- 半径が時間で大きくなる
- 透明度が徐々に下がる
- 複数同時に表示可能
- サビ中は少し明るく大きくする
- 軽量に動作すること

### 8.6 湖面に残る文字

選択された歌詞または言葉を湖面上に残す。

仕様：

- 半透明
- ゆっくり上下に揺れる
- 少し回転してもよい
- 時間経過で薄くなるが、完全には消えない
- サビで一瞬強く光る
- 文字が増えすぎても画面が破綻しないようにする

### 8.7 光の線・星座演出

選択された言葉が3つ以上になったら、言葉同士を細い光の線でつなぐ。

仕様：

- 通常時は控えめ
- chorusでは少し明るくなる
- finalChorusでは完成感を出す
- 線は細く、透明感を持たせる
- 星座のような印象を目指す

### 8.8 言葉の分類

選ばれた言葉を簡易的に分類し、演出に反映する。

分類例：

- 光、未来、夢、希望 → bright
- 夜、静か、深い、涙 → deep
- 歌、響く、声、音、ソナーレ → sound
- 風、空、星 → airy
- その他 → neutral

分類ごとの演出例：

- bright：明るいシアン/白、粒子多め
- deep：青/紫、ゆっくり大きめの波紋
- sound：波紋を大きく、線を少し強める
- airy：粒子を上方向に漂わせる
- neutral：標準演出

### 8.9 エンディング

曲終了時にエンディングオーバーレイを表示する。

表示内容：

- 「あなたが描いた湖」
- 生成された湖タイトル
- 選ばれた言葉一覧
- リセットしてもう一度体験できるボタン

タイトル生成例：

- brightが多い → ひかりのソナーレ
- deepが多い → 静寂のソナーレ
- soundが多い → こえのソナーレ
- airyが多い → 星映しのソナーレ
- その他 → ことばのソナーレ

## 9. 技術構成

このプロジェクトは Vite+ 環境で実装する。

前提：

- 通常のViteプロジェクトだと決めつけない
- Vite+の設定、package.json、既存ディレクトリ構成を確認する
- 既存のVite+構成を壊さない
- 起動、ビルド、チェックのコマンドは package.json と Vite+ 設定から判断する
- npm run dev 固定にしない
- vp コマンドが利用されている場合は、その構成に従う

実プロジェクト構成（確認結果）：

- Vite+ (vp CLI)
- TypeScript (target es2023)
- Vanilla TypeScript（React・Vue 等のフレームワーク不使用）
- pnpm (vp が package manager をラップ)
- エントリーポイント: `index.html` → `src/main.ts`
- 開発サーバー起動: `vp dev`
- 型・lint・format チェック: `vp check`
- ビルド: `vp build`（内部で tsc + vp build）

このため、React版の構成案（hooks 等）は採用せず、Vanilla TypeScript で同等の責務分離で実装する。

外部ライブラリは必要最小限にする。
まずはCanvasと既存フレームワーク(なし)だけでMVPを作る。

## 10. ディレクトリ構成案

Vanilla TypeScript 実装版（本プロジェクトの実構成）：

```
src/
  main.ts                  // エントリーポイント
  style.css                // 全体スタイル（湖面アート用）
  app/
    App.ts                 // アプリ全体の組み立て
  components/
    LakeCanvas.ts          // Canvas描画と波紋・粒子・湖面文字・光の線
    LyricDisplay.ts        // 中央の歌詞表示・クリックハンドラ
    PlayerControls.ts      // 再生・停止・リセット・進行バー
    EndingOverlay.ts       // 曲終了時のエンディング画面
  data/
    mockLyrics.ts          // モック歌詞・セクション境界
  state/
    mockPlayer.ts          // useMockPlayer 相当（再生時間管理）
    lyricTiming.ts         // useLyricTiming 相当（現在歌詞算出）
  types/
    lyric.ts               // 型定義
  utils/
    classifyWord.ts        // 単語分類
    generateLakeTitle.ts   // 湖タイトル生成
```

ReactのhooksディレクトリではなくVanilla用に `state/` を採用する。
責務はReact構成案と同等。

### Phase 3: TextAlive連携

最後に追加する。

## 12. 実装時の注意

- まず動く美しいMVPを作る
- 複雑な水面シミュレーションは不要
- 波紋、反射、光、粒子の組み合わせで湖らしさを出す
- Canvas描画は requestAnimationFrame で行う
- UIフレームワークのstate更新で毎フレーム再レンダリングしすぎない
- Canvas上のアニメーション要素は可能ならrefや内部状態で管理する
- イベントリスナーはクリーンアップする
- 画面リサイズに対応する
- クリック座標とCanvas座標がずれないようにする
- UIはアート体験を邪魔しない
- 歌詞が読めなくなるほど演出を派手にしない
- Vite+の既存設定を勝手に変更しない
- フォーマッタ、リンタ、型チェックはVite+側の推奨コマンドがあればそれに従う
  - `vp check` で format/lint/type の一括検査が走る
