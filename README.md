# 空と灯りのソナーレ

**初音ミク「マジカルミライ 2026」プログラミング・コンテスト 応募作品**
歌詞の風で凧を揚げ、歌詞の灯りで祭りをともす — 昼と夜、ふたつの「湖のソナーレ」。

マジカルミライ2026のテーマ **「湖のソナーレ」** と、開催地・浜松の **浜松まつり（凧揚げ・御殿屋台）** を掛け合わせた Web リリックアプリです。
TextAlive App API による歌詞同期の上に、**スコアや判定のない「駆け引き」型のゲーム性**を載せ、歌詞に触れるたびに世界が応える手触りを目指しました。

---

## 投稿者コメント

> 「空と灯りのソナーレ」は、マジカルミライ2026のテーマ「湖のソナーレ」と浜松まつりを掛け合わせたリリックアプリです。
> 昼は、歌詞をクリックすると湖に波紋が広がり、湖風となって自分だけの凧を空へ揚げます。
> 夜は、歌詞で御殿屋台の提灯を灯し、祭りの通りを巡行します。
> 歌詞のタイプで風や灯りが変化し、サビ前に溜めた力がサビで一気に解放。
> スコアや判定のない「凧揚げ／祭り灯し」の駆け引きとして、最後は到達度に応じた称号が残ります。
> 課題曲6曲すべてに対応しています。

## アピールポイント

### 1. 「歌詞をクリックする意味」を、変換体験として設計
単に歌詞へ当たり判定を置くのではなく、**歌詞 → 自然現象 → 自分の作品が育つ** という一連の変換を中心に据えました。クリックは「勝ち負け」ではなく「風を起こす／灯をともす」ための行為です。

- **昼**：クリックされた歌詞が画面上に立ち上がり、湖へ落ちて **波紋** になる → 波紋が **湖風の流線** へ変わって立ち上る → その風が、開始前に自分で作った **凧** を空へ押し上げる。
- **夜**：歌詞が **光の粒** になり、いま画面を流れている **御殿屋台** へ弧を描いて飛ぶ → 着いた屋台の **提灯がまとめて灯る** → 夜空・湖面・石畳へ反射が広がる。
- どちらも「クリック → 波紋／光の粒 → 風／灯り → 自分の作品が育つ」の**因果が目で追える**ように、発生位置・タイミング・色をそろえています。

### 2. 音ゲーにしない「駆け引き」型のゲーム性
スコア・コンボ・GREAT/BAD 判定・ゲームオーバーは **一切なし**。評価や失敗で急かすのではなく、触れるほど世界が育つ **正のフィードバック** に統一しました。それでも単調にならないよう、凧揚げ／祭り灯しの“間合い”として軽い駆け引きを実装しています。

- **ゲージ（湖風ゲージ／歌灯りゲージ）**：数値は一切出さず、**湖面から自動で立ち上がる風の量・凧糸の発光／提灯の明るさ・屋台の輝き・湖面反射の強さ** で表現。ゲージが高いほど風流線の発生間隔が短くなり、凧糸が明るく太くなります。
- **高度（昼 `altitude`）／明るさ（夜 `yataiBrightness`）**：歌詞で上がり、時間でゆっくり下降。サビ中は上昇量が約1.7倍。到達値は最後の **称号** に直結します。
- **安定度（昼 `stability`）／灯りの持続（夜）**：昼は“適度な間合い”のクリックで安定、放置（数秒の無操作）や **連打しすぎ** で少し乱れ、凧の揺れ・風の線が荒れます。夜は提灯の灯りが時間で弱まり、歌詞で灯し直す“持続”の駆け引きに。**いずれも下限を設け、失敗・ゲームオーバーにはしません**（安定度は最低でも揚がり続ける）。
- **サビ前の溜め（`windReserve`／`lightReserve`）**：サビ直前までに選んだ歌詞を蓄積し、**サビ突入の瞬間に一斉解放**。昼は湖面の波紋が横一列の **風柱** になって凧と周囲の凧が舞い上がり、夜は通りの屋台が **一斉点灯** してバーストが連鎖します。
- **周囲との共鳴**：周りの凧／提灯（`communityKite` / `communityLantern`）が一定数たまった状態でサビに入ると、渦／一斉点灯が大きくなり、上昇量に **共鳴ボーナス** が乗ります。

### 3. 歌詞のタイプで世界の応え方が変わる
`classifyWord`（夜は `classifyWordNight`）による分類で、クリック時の効果・色・演出を変化させました。**どの歌詞に触れるか**が、凧の上がり方や祭りの灯り方に効きます。

| 分類 | 昼（湖風の歌詞凧） | 夜（歌灯りの御殿屋台） |
| --- | --- | --- |
| bright（明） | 上昇風：高度が大きく上がる・光粒が増える | 明灯：提灯が強く光り、明るさが大きく上がる |
| sound（響） | 共鳴風：周囲の凧が光り、出現しやすくなる | 響灯：周囲の提灯が共鳴して光り、増えやすい |
| airy／festival | 追い風：風が強まり、横方向にも大きく舞う | 巡灯：屋台の巡行が一時的に速くなる |
| deep（静） | 静風：安定度が回復、湖の色が深くなる | 余灯：灯りが長持ちし、反射がゆっくり深く揺れる |
| wish（祝） | 祝風：凧の模様が光り、称号に影響 | 祝灯：夜空に星粒、横に光輪が広がる |
| neutral | 標準の湖風 | 標準の歌灯り |

### 4. 昼と夜、ふたつの完成された体験
- **昼の部「湖風の歌詞凧」**：開始前に自分だけの凧（形・色・紋様・願いの文字）を作り、湖風で空へ。曲が進むほど周囲に“みんなの凧”が増え、サビで群舞。最後に到達高度・安定度・共鳴から **称号（flightTitle）** が決まります（例：「祭りの空へ届いた歌詞凧」「みんなの空をひらいた歌詞凧」「荒風を越えた歌詞凧」）。
- **夜の部「歌灯りの御殿屋台」**：屋台を作り、提灯を灯しながら祭りの通りを巡行。**屋台が動くのではなく自分が歩く** 視点で、奥の屋台が左へ流れていきます。手前を **初音ミクのシルエットがプログラム描画で歩く**（後ろへ流れるツインテール＋ティールの淡い縁取り、足踏みアニメ）。明るさ・共鳴・静けさ（deep系の多さ）から **称号（festivalTitle）** が決まります（例：「夜を照らした御殿屋台」「みんなの夜を灯した屋台」「静かな夜に響いた歌灯り」）。

### 5. 課題曲6曲すべてに対応
タイトル → づくり → **曲をえらぶ** → あそぶ、の流れで課題曲6曲（「こたえて」/ imie ほか）から選択。各曲は **リビジョン付き楽曲 URL と音楽地図 ID（歌詞・サビ）を固定** し、再解析の影響を受けにくくしています。グランプリ曲「こたえて」特有の **コーラス（3段落目）1ms問題** は配布データで補正し、主旋律とは別レイヤーで重ねて表示。曲ごとの相性を変える演出（共鳴・巡行など）と合わせ、6曲どれでも世界観が成立します。

### 6. 再生 UI と表記も世界観に寄せる
- **シークバーを廃止**し、曲の進行を **「灯りゲージ」**（進むほど灯がともっていく光の列。先頭の灯はひときわ明るく持ち上がる）で表現。早送りで“答え”に飛ばず、灯していく体験を保ちます。
- **「あそぶ」押下を起点に自動再生**。専用の確認画面を挟まず体験へ直行（自動再生が弾かれても下部の再生ボタンで開始可能）。
- ライセンス表記（**Powered by TextAlive** ／楽曲ページへのリンク）は再生中の曲に合わせて **自動更新**。

### 7. 技術的な作り込み
- **TextAlive 連携の堅牢化**：自然終了で `onStop` を投げないケースに備え、`onTimeUpdate`／`onPause`／`onStop` の三段で終了を検出。さらに「曲頭側を一度通過したか」のガードで、**再生し直し直後の終了誤検知（エンディングが開き直す不具合）** を防止。
- **PixiJS による全描画**：空・湖・石畳・波紋・風の流線・渦・凧／屋台・提灯・粒子・反射・**初音ミク影絵** まで画像素材に頼らずコードで描画。影絵はテーパー帯（二次ベジェ）と `BlurFilter` の発光で構成。
- **昼に手を入れず夜を拡張**：夜の部は昼の共通部品（歌詞表示・プレイヤー・TextAlive 連携・エンディング枠）を再利用しつつ、独立モジュールとして実装。配色は `data-mode="night"` で切り替え。
- **UI の堅牢性**：歌詞をたくさん選んでもエンディングのボタンが押せるよう、カードのスクロール対応＋語数のまとめ表示（「…ほか〇語」）。画面リサイズにも追従。

### 8. 止めて見ても成立する画面の密度
五線譜のように5本で揺れる凧糸、湖面・石畳への反射（屋台・提灯・月光）、過去に揚げた自分の凧の遠景表示（`localStorage`）、瞬く星空と月、周囲の凧／提灯の群舞、屋台ごとに調和色を混ぜた通りの彩り——一枚絵としての完成度にもこだわりました。

## 体験の流れ

```
タイトル（昼／夜を選ぶ）
  └─ づくり（凧づくり／屋台づくり：形・色・紋様・願いの文字）
        └─ 曲をえらぶ（課題曲6曲）
              └─ あそぶ（再生開始）
                    └─ 演奏：歌詞をクリックして風／灯りを起こす
                          └─ エンディング：作品名＋称号＋記録
```

エンディングでは、生成された作品名（kiteName／yataiName）に加え、**称号**・最後に選んだ歌詞・**湖風／灯した提灯の回数**・**共鳴した数** を表示します。「もう一度体験する」で何度でも遊べます。

## 主な機能

- 昼／夜 2モード、各モードに「づくり画面」
- 課題曲6曲からの選択再生
- TextAlive App API による歌詞・サビ同期
- 歌詞クリックによるインタラクション（波紋・風・凧上昇／光の粒・提灯点灯）
- 駆け引き型ゲーム性（ゲージ・高度／明るさ・安定／持続・溜め・共鳴・称号）
- 灯りゲージによる進行表示（シークバーなし）
- 湖面／石畳の反射、星空、群舞、初音ミク影絵（夜）
- エンディング称号生成、過去作品の遠景表示（昼）

## 技術構成

- **Vite+**（`vp` CLI）+ **TypeScript** の Vanilla 構成（フレームワーク非依存）
- **PixiJS 8** による 2D リアルタイム描画（背景・凧／屋台・粒子・反射・影絵）
- **TextAlive App API**（`textalive-app-api`）で楽曲・歌詞・サビを取得
- DOM はタイトル／づくり／曲選択／歌詞表示／プレイヤー／エンディングなど最小限
- 画面状態は `scene = title / setup / songSelect / playing / ending` 相当の遷移で管理
- アニメーションは PixiJS の ticker

## セットアップと実行

### 前提

- **Node.js**（LTS 推奨）
- 本プロジェクトは **Vite+（`vp` CLI）** 上で動作します。アプリのソースは `my-app/` 配下です。
- `vp` はリポジトリには含まれない **グローバル CLI** です。`vp` を導入していない環境でも、後述の **pnpm 経由（フォールバック）** で動かせます（`packageManager: pnpm@10.33.2`／`pnpm-lock.yaml` 同梱）。

### TextAlive App Token の設定（必須）

楽曲・歌詞は TextAlive App API から取得するため、App Token が必要です。

```bash
cd my-app
cp .env.example .env.local        # Windows(PowerShell): Copy-Item .env.example .env.local
# .env.local の VITE_TEXTALIVE_APP_TOKEN を実トークンに置き換える
# 取得: https://developer.textalive.jp/profile
```

- `.env.local` は `*.local` で gitignore 対象のためコミットされません。
- トークン未設定だと楽曲読み込みでエラー表示になります。

### 起動（A: Vite+ の `vp` を使う場合・推奨）

`vp` を導入済みなら最短です（未導入の場合は Vite+（VoidZero）公式の案内に従って導入してください。CI では [`voidzero-dev/setup-vp`](https://github.com/voidzero-dev/setup-vp) が利用できます。導入せずに動かしたい場合は下の **B** を利用）。

```bash
cd my-app
vp install      # 依存をインストール
vp dev          # 開発サーバ起動（表示された localhost を開く）

vp check        # フォーマット・lint・型チェック
vp build        # 本番ビルド
```

### 起動（B: `vp` 未導入・pnpm フォールバック）

`vp` をグローバル導入していなくても、pnpm で依存を入れれば `my-app/node_modules/.bin/vp`（ローカル `vp`）が使えます。

```bash
cd my-app
pnpm install            # corepack 有効化済みなら pnpm はそのまま使える
pnpm exec vp dev        # = ローカル vp で開発サーバ起動
pnpm exec vp build      # 本番ビルド（または: pnpm build = tsc && vp build）
```

### 補足

- 音声付き再生はブラウザの自動再生ポリシーの都合上、**「あそぶ」押下を起点に開始**します（弾かれた場合は画面下部の再生ボタンから開始できます）。
- 本番ビルド時の型チェックは `package.json` の `build` スクリプト（`tsc && vp build`）でも実行できます。

## 設計上のこだわり（補足）

- **音ゲーにしない**：評価・失敗で急かすのではなく、触れるほど世界が育つ正のフィードバックに統一。
- **数値を見せない**：ゲージや高度は数字ではなく光・風・反射で表現し、画面の没入を保つ。
- **昼の世界に手を入れず夜を拡張**：夜の部は昼の共通部品を再利用しつつ独立モジュールとして実装。
- **TextAlive 連携の堅牢化**：曲の自然終了（`onPause`）でも確実にエンディングへ。再生し直し時の終了誤検知も防止。
